# Figma 평면도 규칙

`processFloor.js`는 레이어 이름(id)으로 요소를 구분한다. 내보내기 전에 아래를 지킨다. 내보낼 때 "Include id attribute"를 켠다.

## 최상위 레이어

| 레이어 | 내용 |
|---|---|
| `Visual` | 벽·방·문·아이콘·번호 글자 전부 |
| `Hitbox` | 방마다 탭 영역 도형 하나. 없으면 `processFloor.js`가 멈춘다 |

## Hitbox

- 이름은 `room_{호실}` — 예: `room_506-1`, `room_열람실`, 지하는 `room_B404`.
- 한 강의실이 여러 조각이면 `room_623`, `room_623_2` — 같은 방으로 묶여 함께 선택되고 번호는 한 번만 보인다. **서로 다른 방에 같은 번호를 붙이면 둘이 같이 선택된다.**
- rect(회전 가능)·path·circle 지원. 곡선은 점 여러 개로 근사된다.
- fill이 없으면 Figma가 도형을 빼고 내보내므로 아주 옅은 fill-opacity를 준다.

## Visual 안의 번호 글자

- 번호 글자는 `<path id="301">`처럼 한 덩어리로 내보내진다. 앱은 이 글자를 지우고 Hitbox 이름으로 다시 그린다(지도를 돌려도 똑바로 서게). 그래서 **화면에 보이는 번호는 Hitbox 이름**이다.
- "계단 세미나실"처럼 글자로 된 방 이름도 Hitbox 이름과 같으면 지운다.
- 번호 레이어 이름은 실제 글자와 달라도 앱에는 영향이 없다(Figma가 "106", "106_2"처럼 복사한 이름을 쓰는 경우가 많다). 다만 `auditFloors.js`가 비교할 수 있게 실제 번호로 두면 좋다.
- 문: `door`, `door_2` … / 계단·엘리베이터: `map_stairs`, `map_elevator` …

## 자주 나는 실수 (실제로 있었던 것)

| 실수 | 앱에서 보이는 증상 | 예 |
|---|---|---|
| 다른 층 Hitbox를 복사해 와서 이름을 안 바꿈 | 방이 없는 자리에 번호가 뜨거나, 번호가 다른 층 번호 | L_1(2층 것), L_9(8층 것) |
| Hitbox 이름 오타 | 번호가 틀리게 보이고 길찾기가 장소를 못 찾음 | `room_2002`(202), `room_778`(728) |
| 두 방에 같은 번호 | 하나를 누르면 둘 다 선택 | L_3 `303`/`303_2`(305) |
| 지하 번호의 B 누락 | `306`처럼 보임. 기존 방은 처리 스크립트가 예전 JSON의 B를 이어받아 가려지지만, **새로 그린 방은 그대로 드러난다** | R_B3, R_B4 `room_402`(새 방) |
| 비틀린(자기교차) path | 엉뚱한 곳을 눌러도 그 방이 잡힘 | S_1 창고(강당을 X자로 가로지름) |
| 번호는 그렸는데 Hitbox 없음 | 눌러도 반응 없음 | G_4 422, R_B4 B402 |
| 덮인 문이 남아 있음 | 방 안에 문이 보임(앱은 문을 맨 위에 그린다) | R_B3 B308 |
| 한 도면을 두 층 파일로 내보냄 | 같은 도면이 두 번 등록, 다른 동 방이 이 동으로 보임 | H_1 = G_4 사본 → [decisions.md](decisions.md) |

`auditFloors.js`가 위 대부분을 잡는다.
