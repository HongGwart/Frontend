# 평면도 데이터 결정 기록

새 결정은 위에 추가한다. 날짜, 무엇을, 왜.

## 2026-10-23 · H동 1층은 G동 4층 도면의 위쪽 날개로 연결, H_1 파일 삭제

- **상황**: `H_1.svg`는 `G_4.svg`와 내용이 같은 사본이었다(위쪽 날개 101~106 = H동 1층, 아래 4xx = G동 4층). 지도 기준점도 없어 지도에 안 깔렸고, H동 1층에서 410을 누르면 "H동 410호"로 나왔다.
- **결정**: H_1 파일을 지우고 `hostedFloors.json`에 `"H_1": { "floorId": "G_4", "maxY": 335 }`(날개 아래 벽 y≈330). 아래 J동과 같은 방식.
- **주의**: Figma에서 다시 내보낼 때 H_1을 `FLOOR_MAPS`에 다시 넣지 않는다.

## 2026-10-23 · 도면 번호의 자기 동 글자는 뗀다

- H동 3~6층 Hitbox는 "H317"처럼 동 글자가 붙어 있는데 서버는 "H동 317호"다. `getRoomOwner`가 `^{동}\d`면 뗀다. 지하 표시 B(G동 B110, R동 B212)는 동 글자가 아니라 그대로 둔다.

## 2026-10-22 · 배경 SVG에서 글자로 된 방 이름도 지운다

- **상황**: `stripLabelPaths.js`가 숫자 번호만 지워서 "계단 세미나실", "Hall" 같은 이름이 배경과 앱 라벨로 두 번 그려졌다.
- **결정**: `processFloor.js`가 방 JSON을 먼저 만들고 `stripLabelPaths.js --rooms=<json>`으로 방 이름과 같은 path도 지운다(지도용 PNG는 원래 이 기준으로 지우고 있었다).

## 2026-10-22 · J동은 L동 도면 아래쪽, 지도에선 화면마다 다르게

- **상황**: J동(제3공학관)은 자기 도면이 없고 L동(와우관) 4~8층 도면 아래쪽에 J로 시작하는 호실로 들어 있다. 서버는 "J동 101호"(J동 1층)처럼 J동 기준 층을 준다.
- **결정**:
  - `hostedFloors.json`: `J_B2~J_3` → `L_4~L_8`, J동 부분은 `minY: 740`(계단 3개 연결 통로 아래 복도 + 호실 줄).
  - 방 소속은 위치로 정한다: 도면에서 그 동 부분 안에 있는 방은 그 동(`getRoomOwner`). 카드·즐겨찾기·길찾기가 서버 이름과 맞는다.
  - 지도에 깔 도면: **검색**은 그 동 부분만 잘라 구운 PNG(`J_1.png`), **길 안내**는 L동 전체 도면(L동 계단·통로로 이어지는 길이 보여야 해서), **건물 내부 보기**도 L동 전체.
- **도면은 두 가지뿐**: 잘라 구운 PNG(검색용)와 원래 L동 도면. 길 안내용 도면을 따로 만들지 않는다.

## 기준점·PNG

- 지도 위치는 서버 평면도 꼭짓점 두 개 + Figma 기준점 두 개로 닮음 변환(이동·회전·균일 확대) → 네 모서리(`floorPlanAnchors.json`). 손으로 찍은 기준점은 쓰지 않는다(2026-10-21부터).
- 네이버 GroundOverlay는 SVG를 못 받고 남북 정렬 사각형에만 펼치므로, 빌드 때 도면을 돌려 투명 PNG로 굽고 region을 같이 저장한다. 번호·아이콘은 PNG에서 빼고 앱이 마커로 똑바로 그린다.
