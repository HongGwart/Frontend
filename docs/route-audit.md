# 길찾기 경로 검사

dev 서버(`GET /api/route`)에 실제 경로를 요청하고, 앱의 `toRouteView`로 바꾼 경로 카드 구간 목록에서 문제를 찾는다.
스크립트: [scripts/auditRoutes.js](../scripts/auditRoutes.js). 검사 항목은 스크립트 머리 주석에 있다.

## 돌리는 법

서버가 경로를 요청마다 실시간으로 계산해서 **하루 50건(2초 간격)씩만** 돌린다. 진행 위치는
`scripts/routeAudit/state.json`에 남아서 다음 실행이 이어서 한다. 요청 한 건이 세 모드(최단/실내 위주/계단 회피)를 다 준다.

```
node scripts/auditRoutes.js               # 오늘 분 50건
node scripts/auditRoutes.js --report      # 요청 없이 누적 결과만
node scripts/auditRoutes.js --reinspect   # 요청 없이 저장된 응답을 지금 앱 코드로 재검사 (앱을 고친 뒤)
node scripts/auditRoutes.js --recheck     # 문제 나온 경로만 서버에 다시 요청 (서버가 고친 뒤, 한도 적용)
```

- 테스트 장소는 `scripts/routeAudit/places.json`(자동완성으로 모은 건물 21개, 호실 약 900개)이다. 전체 800건:
  건물 ↔ 건물 380, 같은 건물 최저층 ↔ 최고층 38, 다른 건물 호실 ↔ 호실 342. D동은 그래프에 연결되지 않아 뺐다.
- 응답 원본은 `scripts/routeAudit/responses/`에 저장되고 커밋하지 않는다. 2026-10-23 첫 50건은 저장 기능 전이라 원본이 없다.

### 서버(백엔드)에 요청할 것

**계단 회피 경로에 계단이 들어감** (`stairs-in-avoidance`)
- 실내 계단: A·B·C·E동 → Q동 계단 회피 경로에 "계단 이동: G동 1층 → 2층".
- 야외 계단: F동을 오가는 경로와 I동으로 가는 경로 대부분에 야외 계단 1곳. F동에서 나가는 계단 회피 경로는 출발 직후
  F동 남측 출입구 앞 계단(8m)을 지나고, 거리도 최단 경로와 같다(F동 → A동 둘 다 128m). 야외 계단에는 회피 가중치가
  아예 안 걸리는 것으로 보인다.
- I동은 P동으로 가는 경로를 빼고 오가는 계단 회피 경로가 전부 "I1 남서측 계단 출입구" 앞 야외 계단(5m)을 지나 L동 7층으로
  이어진다. I동 출입구 대부분이 계단으로만 연결돼 있어 피할 길이 없는 것인지, 회피 가중치가 없는 것인지 서버 확인이 필요하다.

- A동 ↔ B동 ↔ C동 사이 공용 통로 안의 계단도 계단 회피 경로에 들어간다(예: B동 203호 → A동 103호).
- 같은 건물 안: C동 8층 ↔ 9층, F동 1층 ↔ 2층·5층 ↔ 6·7·8층(F동 6~8층 호실에서 나가는 계단 회피 경로는 전부 5층까지 계단), G동 지하 1층 ↔ 1층, Z1동 1층 ↔ 2층을 계단 회피에서도 계단으로 간다.
  그 층에 엘리베이터가 안 서서 피할 수 없는 것인지 확인이 필요하다. 피할 수 없다면 앱에서 "계단을 피할 수 없는 경로"
  안내를 띄우는 방향을 같이 정한다.
- P동 1층 호실에서 나가는 계단 회피 경로는 대부분 P동을 나와 야외 계단 1곳을 지나 Q동 4층으로 들어간다.
- J동 001-1호 ↔ J동 301호: 같은 건물인데 건물 밖으로 나가 L동·Q동을 거쳐 다시 들어오고, 야외 계단을 5곳 지난다.
  J동 안에서 층을 잇는 연결(계단·엘리베이터)이 그래프에 없는 것으로 보인다.

**같은 건물 안에서 경로가 없음** (`no-route`)
- I동 104-3호 ↔ I동 614호, MH동 101호 ↔ MH동 1408호. 같은 건물인데 경로가 없어서 층 사이 연결이 끊긴 것으로 보인다.
- 다른 건물에서 I동 314·401·403·405·406·407호, MH동 309·401·402·403·501·502호로 가는 경로도 없다.
- 직접 확인(2026-10-23): A동 → MH동 101호는 경로가 있다(89m). MH동은 1층은 이어지고 3층 이상이 떨어져 있는 것으로 보인다.
  MH동 6~8층 호실(601~611·701~713·801~804호)에서 다른 건물로 나가는 경로도 18건 전부 없다.
- A동 → I동 104-3호는 경로가 없는데, I동(건물) → I동 104-3호는 있다(4m). I동 건물 노드의 출입구 중 104-3호 쪽 출입구는
  캠퍼스의 나머지와 이어지지 않은 것으로 보인다.
- **I동 호실은 1~6층 전부 다른 건물과 오가는 경로가 없다.** I동에서 나가는 18건(107·109·201~213·608~614·104-3호 →
  다른 건물 18곳)과 다른 건물에서 들어오는 경로 모두 404. I동 건물 노드로는 길찾기가 되지만 호실은 안 된다.
- L동 306호(nodeId 2945)는 들어가는 경로(G동 B108호 →)도 나가는 경로(→ P동 605호)도 없다. 바로 옆 L동 305호 → 306호,
  L동(건물) → 306호도 경로가 없다. 노드와 문(entrance, ROOM_DOOR)은 서버에 있는데, 문에서 복도로 이어지는 간선이 빠진 것으로 보인다.
- Z1동 호실(106·107·108호)도 다른 건물에서 가는 경로가 없다. Z1동 건물 노드와 같은 원인으로 보인다.

**경로를 찾지 못하는 건물** (`no-route`, 404 `ROUTE_NOT_FOUND`)
- D동(nodeId 2411)은 들어가는 경로도, 나가는 경로도 전부 없다(다른 21개 건물 모두). 그래프에서 완전히 떨어져 있다.
  이후 테스트에서는 D동을 뺀다(스크립트 `EXCLUDED_BUILDINGS`). 서버가 고치면 빼고 `--recheck`로 확인한다.
  서버의 D동은 건물 노드 하나뿐이다: 출입구(`entrances`)가 비어 있고, 호실이 검색되지 않는다("D동 0105" 등). 앱 평면도에는
  D동 지하 1~5층(호실 48개, 번호 0101~0504)이 있어서, D동 호실은 출발/도착을 누르면 "길찾기를 지원하지 않는 호실" 안내가 뜬다.
- Z1동(5510)도 D동처럼 들어가는 경로도, 나가는 경로도 전부 없다(다른 19개 건물 모두). Z1동 안의 호실끼리(101호 ↔ 207호)는 경로가 나온다. 건물 밖과 이어지는 연결만 없는 것으로 보인다.

**실외 구간 이름 없음**
- 실외 step의 `road`·`landmark`가 항상 `null`이라 앱은 "건물 밖"으로만 보여준다.

## 해결됨

**실내 공용 통로가 "건물 밖"으로 나오고, 통로 안 계단이 "계단으로 층 이동"으로 나옴** (`unknown-floor`, `indoor-exit`) — 2026-10-23
- 예: A동 → B동 실내 위주 (`1367->1368`). 첫 50건 중 33건.
- 서버는 건물 사이 실내 통로를 `EXIT_BUILDING`(`context.indoor: true`, 건물 없음, "A동에서 공용 통로로 이동하세요") →
  `FLOOR_CHANGE`(건물·층 없음) → `ENTER_BUILDING`으로 준다.
- `toRouteView`가 실내 `EXIT_BUILDING`은 "공용 통로" 실내 이동으로 시작하고, 건물 없는 계단은 야외 계단처럼 지금 구간에
  "계단 N곳 포함"으로 합치게 고쳤다. A동 → B동: "실내 이동 · 계단 1곳 포함: 공용 통로 → B동 1층".
- state.json의 나머지 32건은 응답 원본이 없어 재검사 전이다. 다음에 `--recheck`로 다시 요청하면 지워진다.

**공용 통로 엘리베이터가 "계단 1곳 포함"으로 나옴** (`stairs-in-avoidance` 오탐) — 2026-10-23
- A·B·C동 사이 공용 통로의 엘리베이터도 서버가 건물·층 없는 `FLOOR_CHANGE`(`transport: ELEVATOR`)로 준다. 위 수정이 건물 없는
  층 이동을 전부 계단으로 세어서, 계단 회피 경로 5개에 없는 계단이 표시됐다(예: A동 103호 → B동 301호).
- 이제 `transport`를 보고 "엘리베이터 N회 포함"으로 따로 센다. 경로 카드의 계단·엘리베이터 수와 구간 목록이 전 경로에서 일치한다.
